# Reference acceptance suite

The 30 task fixtures of spec §19.2 (TODO 6.5): `at-01` to `at-20` are feasible across the shipped recipes, `at-21` to `at-30` deliberate conflicts, policy and missing-evidence cases. An agent wrote them; the suite counts once the owner has reviewed them (GAPS Q28). The design is ARCH 2026-11-16, milestone 6, acceptance suite.

Each `<id>.task.json` holds the task as `architect_plan prepare` takes it, the recipes `propose` may build (`recipeIds`), bindings for open slots (`proposals`), the expected outcome and, for a conflict, the blocker category of spec §9.5. `live` says how far the live runner takes it: `render` plans, approves and renders it on the reference target; `plan` plans it there and stops; `fixture only` runs only in the CI test, because it changes the environment (`environment`: another target URL, a model file removed). `refused` means the task is rejected as malformed before planning (AT-01).

The input images are synthetic, listed in `inputs.json` and generated by the live runner into `architect-acceptance/` in the target's input folder, never over an existing file: `scene` is a landscape of flat shapes (sky, hills, a sun), `stripes` a diagonal colour pattern, `mask-disc` a white disc on black, a quarter of the image across, in the centre. The CI test takes their sizes from `inputs.json`.
